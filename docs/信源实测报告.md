# 信源可采性实测报告

> 探测脚本：`intel-station/scripts/probe_sources.py`（首页级）、`probe_round2.py`（针对性验证）
> 原始结果：`intel-station/config/source_probe.json`、`source_probe_round2.json`
> 探测时间：2026-09-06

---

## 0 · 一句话结论

**27 个候选信源中 18 个拿到了可靠的直采通道**（原生/直连 RSS 6 + RSSHub 7 + 直抓 5），9 个只能靠 Exa 间接覆盖。

同时，实测**推翻了技术方案 §4 的一个核心判断**：原方案称"RSSHub 定向订阅是 B/E 类主通道（公众号）"——**公众号直采通道基本不成立**，详见 §3。

## 3 · 公众号通道：原判断被推翻

技术方案 §4 原文称「RSSHub 定向订阅覆盖 B/E 类主通道（公众号），是 v1 缺的最大一块」。实测证明这个判断站不住。

### 3.1 证据链

**① RSSHub 官方源码自述**
`lib/routes/wechat/namespace.ts` 明写：「公众号直接抓取困难，故目前提供几种间接抓取方案，请自行选择」。

**② 5 个微信路由族用官方示例 ID 实测，仅 1 族存活**

| 路由族 | 官方示例 | 结果 |
|---|---|---|
| `/wechat/wechat2rss/:id` | `5b925323...` | ✅ 5 条 |
| `/wechat/ce/:id`（CareerEngine） | `595a5b14...` | ❌ |
| `/wechat/ershicimi/:id`（二十次幂） | `813oxJOl` | ❌ |
| `/wechat/sogou/:id`（搜狗） | `qimao0908` | ❌ |
| `/wechat/uread/:userid`（优读） | `shensing` | ❌ |

**③ 唯一存活的 wechat2rss，免费列表 395 个号，只命中 3 个目标**
机器之心、量子位、42章经 —— 且列表整体偏安全/技术类，电商与商业深度类几乎没有。晚点、卡兹克、字母榜、光子星球均不在内。

**④ wechat2rss 私有部署可覆盖任意公众号，但有许可限制**
150 元/年，用户协议明确：「**仅允许个人学习和研究使用，禁止商用和内容分发**」。本项目会公开部署并展示内容摘要，落在协议的灰色地带。

### 3.2 决策：不走公众号直采，改做「原始出处归因」

放弃公众号直采，代之以一个更贴合中文互联网生态的机制。

**事实前提**：深度内容首发在公众号，但会大量扩散到可采站点。晚点的独家会被 36氪/虎嗅/新浪转载，卡兹克的文章会被聚合站搬运。

**机制设计**：在抽取阶段（S3）识别正文中的原始出处标记——「据晚点LatePost报道」「来源：字母榜」「转载自XX」——为 item 增加字段：

```
item.source_id        = "36kr"        # 我们实际采到的载体，C 类
item.original_source  = "latepost"    # 识别出的原始出处，B 类
item.source_class     = "D"           # 本条是转载
item.effective_class  = "B"           # 归因后的一手性等级
```

**三重收益**：
1. **保留一手性信号** —— 知道这条源头是晚点独家，置信度按 B 类算，不会被误判成"单源待确认"
2. **转载识别一鱼两吃** —— 同一套机制既做核验（§5.2 拒绝台账），又做归因
3. **诚实** —— 明确区分"我采到的"和"信息真正的源头"，这本身就是核验严谨性的体现

**归因结果需人工抽检**，纳入 §12 的人工复核节点。

## 5 · 覆盖度评估

| 通道 | 数量 | 占比 |
|---|---|---|
| rss（原生 / wechat2rss 直连） | 6 | 22% |
| rsshub | 7 | 26% |
| direct（直抓 SSR） | 5 | 19% |
| exa（仅间接） | 9 | 33% |
| **合计** | **27** | — |

**67% 的信源有确定性直采通道**（不依赖搜索召回），相比 v1 的 100% 依赖 Exa 是结构性改善——直采通道意味着：定向、稳定、零 LLM 成本、不受搜索词覆盖度限制。

**剩余 33% 走 Exa 的信源中，两个是遗憾**：
- **晚点 LatePost**（B 类情报密度最高）
- **亿邦动力**（电商垂类最专业）

这两家将高度依赖 Exa 召回 + 转载归因。需在查询矩阵（§4.1）中为它们单独设计站内检索词，并在信源健康度表（§3.4）中重点监控其命中率。

## 5.5 · 首轮实跑修正（2026-09-06 补记）

D3–D4 实跑后，**本报告 §2 的 `direct` 通道判定被推翻 3 个**。

**原因：我用「首页 SSR 中文字数」作为可采性的代理指标，这个指标不可靠。**
首页字数多可能全是导航、页脚与营销文案；真正决定能否采集的是**文章级链接结构**——
页面里有没有服务端渲染出的文章链接。

| 信源 | 原判定 | 实跑结论 | 修正 |
|---|---|---|---|
| 阿里巴巴集团 | direct（SSR 23026 字） | 新闻列表为客户端渲染，抓回来的全是 `Investor Relations`、`Culture and Values` 等菜单项 | → `exa` |
| 字节跳动招聘 | direct（SSR 4599 字） | 岗位列表客户端渲染，无服务端文章链接 | → `exa` |
| 巨量引擎 | direct（SSR 993 字） | 首页只有课程入口，无新闻 | → `exa` |
| 界面新闻 | direct | ✅ 成立，13 条/轮，URL 形态 `/article/<数字>.html` | 保留，加 `article_url_pattern` |
| 电商报 | direct | ✅ 成立，URL 形态 `/p/<26位ID>`，通用正则匹配不到 | 保留，加专用 `article_url_pattern` |

**通道分布修正后**：rss 6 / rsshub 7 / direct 2 / exa 12。直采覆盖率从 67% 降至 **56%**。

**方法论教训**：可采性必须在**文章级**验证，不能用首页指标推断。此教训已反映在 §6 待办中。
