# 怎么用这个站

五分钟看懂每个页面在回答什么问题。想了解为什么这么设计，看
[`方法论.md`](方法论.md)；想自己跑起来，看 [`运行说明.md`](运行说明.md)。

---

## 五个页面，五个问题

| 页面 | 回答的问题 |
|---|---|
| **运行回放** | 这些结论是怎么来的？——一次完整跑批的漏斗，每一级都能点进去看被淘汰了什么 |
| **事件库** | 行业里发生了什么？——可按主体 / 领域 / 状态 / 置信度筛，点进去看事实与信源 |
| **周报** | 这一周的格局是什么？——跨事件的判断，每条结论锚定事件编号可回溯 |
| **定制简报** | 我关心的那件事怎么样了？——输入问题，现场检索知识库与互联网生成 |
| **信源** | 这些信息从哪来？——按一手性分组的信源清单 |

首页是**运行回放**而不是事件列表，这是刻意的：这个站的主张是「过程即产品」，
你应该先能质疑它，再决定信不信它。

## 三个要先知道的标记

**① 置信度**（五档，规则算出，模型不参与）

> 官方确认·多源印证 → 官方一手 → 多源已验证 → 深度单源 → **单源待确认**

只有一个信源支撑的事件会明确标成「单源待确认」，不会被包装成已核实。
看到这个标记，意味着系统在提醒你：这条还没被交叉验证过。

**② 落地阶段**（概念宣传 / 试点探索 / 已上线 / 规模化应用）

行业惯例是把试点说成上线。系统对官方口径**取保守值**，并在事件详情里
写明依据，例如「官方称『已上线』，第三方报道显示『试点探索』，取保守值」。

**③ 事实 / 推断 / 建议**（详情页三段分开显示）

- **事实**必须挂着信源链接，点得进原文
- **推断**会标明「是谁的判断」
- **建议**没有信源——**能追溯到某篇文章的就不是建议，是别人的观点**。
  建议由本系统基于全局事实生成，涉及我方效果的一律标「需内部数据验证」

## 怎么核对一条结论

以周报里的一条关键发现为例：

```
关键发现 → 点它下面的 EV-xxxxxxxx 编号
        → 进入事件详情
        → 看「事实」区块，每条事实后面是信源名 + 发布时间
        → 点信源 → 跳转原文
```

如果对某条存疑，也可以反过来查它**为什么没被淘汰**：首页漏斗的每一格都能
点进拒绝台账，看到同一轮里被判为重复、旧闻、无关的条目分别是哪些、
因为什么被拦下。

## 定制简报怎么用

输入框里写具体问题，例如：

- 「对比各平台 AI 导购的落地阶段差异，哪些做法对我方商家工具有借鉴价值？」
- 「只讲快手一家，梳理它的 AI 动作时间线」

系统会先解析意图，再**同时检索知识库与互联网**，两类材料在报告里分区标注：

- **A 知识库事实** —— 走过完整核验链路，带事件编号，可追溯
- **B 互联网检索** —— 本轮实时抓取，**未经本系统核验**

两者冲突时报告会说明分歧，不会强行统一成一个说法。不填问题直接点生成，
则退化为「最近 15 条知识库内容的综述」，不发起互联网检索。

输入框的三种状态对应三个阶段：静止时是液态金属环，生成中是流动光带，
生成结束恢复普通线条框。

## 更新频率与时效

每天两轮（北京时间 08:30 / 20:30）。数据从跑批到线上最慢约 15 分钟
（GitHub raw 的 CDN 缓存 + Worker 边缘缓存）。页面底部标着快照时间。

事件的时间锚点是**事情发生的时间**，不是系统发现的时间——所以回填的历史事件
会正确显示为「旧闻/背景」，不会混进本周新增。

## 看到这些不必惊讶

- **单源事件占多数**。这是真实的信息环境，系统选择标注而不是隐藏。
- **A 类（当事方直述）信源产出极少**。中文电商垂类的官方渠道大多是
  CSR 页面或需登录，抓不到；这是当前最大的覆盖短板，写在局限里。
- **周报里的「方法论备注」会自曝不足**，例如「本期某某为单源报道，需后续
  多源验证」。这是刻意的——一份不说自己边界的情报报告没法用。
